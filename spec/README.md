# Specification

Versioned and frozen. Code references specification sections by version, never
by a moving document.

- `draft/` — working draft; **nothing here is frozen**
- `v3/` — current frozen version, to be cut from `draft/` as sections settle
- `vectors/` — conformance test vectors (CC0-1.0)

Freezing is a promise that an encoding will never change again; `draft/` makes
no such promise. A section moves into a numbered version directory unchanged
when it is judged stable, and only then does the freeze rule apply to it.

## Test vectors come first

Vectors are written **before** the implementation, directly from the
specification. Writing them is how specification ambiguity is discovered, and it
is far cheaper to discover it here than in a consensus debugger.

The vectors are also the artefact that survives if the implementation does not:
a specification with conformance vectors is reimplementable by someone else. A
specification in prose is not.

Planned coverage: canonical serialisation, address derivation and Bech32m,
sparse Merkle tree hashing convention, transaction envelope, 2D nonce layout
(lane, sequence), state transition per transaction type.

Present coverage: canonical serialisation including a rejection set, the domain
separation registry, hash chains, Merkle list roots, key derivation, account and
device identifiers, and Bech32m addresses with their rejection set.

The vectors are generated by [`../tools/vectorgen/`](../tools/vectorgen/), a
second implementation written from the prose in `draft/` and deliberately not
from the Rust. Where the two disagree, **the disagreement is the finding**:
neither wins automatically, and the bug is as likely to be in the prose as in
either program.
